# Network Proxy 使用说明

在应用“选项”里仅填写 `controller_secret`：由你自己生成并保存的至少 16 字符随机密钥，用于配套集成连接，不是订阅服务或 OpenClash 的密码。

启动后打开 Web 界面：

1. **代理配置**：填写订阅 URL 和可选扩展 YAML，或局域网共享代理地址、协议、上游账户。保存订阅时立即拉取、合并、校验、加载；失败保留旧配置。
2. **代理出口**：选择“订阅配置”或“局域网共享代理”。不列出所有订阅节点，实际节点按订阅策略组与规则选择。
3. **流量范围**：显式模式供客户端主动接入；整台 HAOS 模式通过 TUN 接入 Core 和应用公网出站；部分模式勾选应用或集成。按应用仅支持独立 bridge IPv4 容器，host-network 应用不可单独隔离。按集成需配套集成，只覆盖带 HA 配置条目上下文的 aiohttp 请求。
4. **代理模式**：规则模式保留配置规则；全局模式通过当前来源的出口组；直连模式由 Mihomo 直接连接。
5. **局域网共享**：两种来源均可分享，其他设备设置 HA 局域网 IP 的 HTTP / SOCKS5 7890 端口。可选共享账户与上游账户互相独立；关闭共享时只有本机可以连接。
6. **连接配套集成**：复制网页中的控制、管理与出口内部地址，控制密钥使用自己设置的 controller_secret。连接表单不需要填写代理用户名/密码。

订阅扩展对象递归合并、列表替换；`prepend-rules` 插入订阅规则前，`append-rules` 插入 MATCH 前。策略组名称必须存在。应用管理的监听、控制和 TUN 不可覆盖。HTTP / inline 提供者保留，任意本地文件提供者不支持。

局域网发现按需扫描最多 256 个私有 IPv4 地址，探测 7890、7891、7893、1080、8080，完成代理握手才显示。需要认证时填写上游账户后保存；非标准端口可手动填写。

管理入口与私有地址在透明接入时保持直连。UDP 需要上游支持，HTTP 上游不提供 UDP。配套集成每 10 秒同步，网页保存不会自动重载其他集成；观察捕获请求计数确认接入情况。

0.4.0 改用主机网络，需要 TUN 和网络管理权限。升级前备份并检查端口冲突，辅助集成同步升级；默认仍为显式模式。Linux CI 验证与实机 HAOS 验收是不同步骤。源码、验证方法和升级说明见仓库 README。

透明接入时应用固定使用 redir-host DNS 模式，避免局域网名称被转换为虚拟地址；订阅的上游 DNS 与其他 DNS 策略仍保留，常见本地名称默认使用系统 DNS。


0.4.1 启动恢复：若保存的配置被内核拒绝，网页保持可用并显示不含凭据的错误分类。原设置和订阅快照保留，恢复内核的出口为 REJECT，透明代理和局域网共享保持关闭。修正后成功保存会保持显式模式；需要时再启用流量接入和共享。恢复期间配套集成同步返回错误，已加载的请求路由策略不会被清除。此修复改善可恢复性与诊断，不代表所有真实订阅错误已得到修正。

Ingress 端口由 Supervisor 自动分配，无需在选项或网页设置。管理服务先预留回环 API 9091 和分配的 Ingress 端口，再启动内核及路由；如果日志出现 management_port_in_use:9091，需要检查该端口的已有服务。应用不会终止其他服务或静默更换集成地址。
