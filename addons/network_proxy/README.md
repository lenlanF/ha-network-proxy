# Network Proxy

为 Home Assistant OS 提供 Mihomo 代理出口。保存订阅时立即拉取完整配置，保留策略组与规则，并支持网页 YAML 扩展、局域网共享代理发现和出口分享。

应用“选项”仅填写 controller_secret，其余设置在 HA Ingress 网页中管理。出口选择“订阅配置”或“局域网共享代理”；支持规则、全局、直连模式，以及整台 HAOS 或部分应用与集成的接入范围。网页提供配套集成的内部地址复制入口。

当前为 0.5.0 开发预览。amd64/aarch64 镜像由 GitHub Actions 构建并测试，HA 直接下载预构建镜像。整台 HAOS 接入仍需实机验收。部分应用仅支持独立 bridge IPv4 容器；部分集成仅覆盖带配置条目上下文的 aiohttp 请求，需要配套集成。

升级会改用主机网络和 TUN，配套集成也需更新至 0.4.0。默认保留显式模式，不会自动接管整台 HAOS 流量。详细步骤见 [使用说明](DOCS.md)。

出口测试失败时点击“诊断连接”。诊断检查已保存的 HTTP 上游认证及两个固定 HTTPS 目标，区分 HTTP 407、超时、DNS、拒绝连接和证书错误，不显示密码或原始错误内容。握手成功只证明建立代理隧道；HTTPS 测试成功只证明该目标通过出口可达，不代表所有站点或 HA 集成都已接入。


0.4.1 启动恢复：若保存的配置被内核拒绝，网页保持可用并显示不含凭据的错误分类。原设置和订阅快照保留，恢复内核的出口为 REJECT，透明代理和局域网共享保持关闭。修正后成功保存会保持显式模式；需要时再启用流量接入和共享。恢复期间配套集成同步返回错误，已加载的请求路由策略不会被清除。此修复改善可恢复性与诊断，不代表所有真实订阅错误已得到修正。

0.4.2 修复 emoji 名称触发的配置解析失败，覆盖启动、首次保存、热加载和持久化读取。原订阅和名称可以继续使用，无需删除 emoji。

0.4.3 使用 Supervisor 动态分配的 Ingress 端口，避免固定 8099 与已有服务冲突。配套集成内部地址不变，无需为本次应用修复重启 HA Core。

0.5.0 增加独立代理开关、多订阅、原生模式、策略组选择和配置编辑。关闭代理后管理界面继续运行。辅助集成需同步复制更新至 0.5.0 并重启 HA Core；旧版要求 PROXY 策略组而无法连接新应用。原单订阅与已保存设置会迁移，应用选项仍只保留 controller_secret。
